# Bifrost Registry — interactive design prototype

The laboratory imports the pinned Bifrost Postman collection: **3,530 requests in 114 top-level folders**. All tests / Custom preserves a custom subset. Folder and request names, bodies, paths and inherited named assertions come from the source. One target selector stores exact access IDs; creator, provider, group and task filters narrow that selector, and unchecking an access excludes it. Preparation ends in a source request preview. It does not execute provider requests or rewrite arbitrary official tests for another model.

The Runs view accepts Newman JSON reports and shows messages, requests, responses, assertions and recorded lifecycle events when present. Imported reports remain in browser memory across navigation. **Open recorded loopback demo** uses real Newman 6.2.1 output from three official requests against an isolated local stub: two passes and one deliberate failure. Its responses are synthetic and establish no Bifrost/provider capability. Playback timing is a UI replay, not a live gateway connection. The native Bifrost monitor provides aggregate progress; individual request events require a runner bridge that is not implemented here.

Source regeneration: `node scripts/import-harness.mjs /path/to/provider-harness.json public/harness-catalog.json`. The pinned source revision and SHA-256 are recorded in the generated catalog. To recreate the demo report, install `newman@6.2.1` in a temporary directory and run `node scripts/record-harness-demo.mjs /path/to/provider-harness.json /absolute/path/to/node_modules/newman/index.js`. This recorder binds only to `127.0.0.1` and uses no credentials. Sources and limits are in [the UI references](../bifrost-ui-patterns.md#harness-and-plugin-boundaries).

From this directory, run `npm ci` then `npm run dev -- --port 4173 --strictPort`. Open http://127.0.0.1:4173/. Run `npm run build` and `npm run check` to verify compilation and demo state logic.

Registry records and API responses are illustrative; locally imported Newman reports retain their recorded evidence. State is held in browser memory. Refresh or **Demo settings → Reset demo** resets the demo. View defaults in **Settings** persist separately in localStorage. Its proposed `config.json` export is a UI preference contract, not an import-ready plugin config or runtime synchronization. Creator, serving provider, usage, modalities and capabilities are separate catalogue fields; grouping the catalogue is for browsing and does not create routing groups. The group editor also offers a native Creator → Model → Access tree: only model selection changes group membership. The `google` access ID in fixtures represents a simulated Google AI Studio access, not Vertex. No gateway, credentials, provider calls, or production data are used. The optional **Quick tour** can be restarted from the header. Sofian's UX approval is still pending; this prototype is not the UI currently served by the plugin.

The React UI primitives in `src/components/ui/`, `src/hooks/`, `src/lib/utils.ts`, `src/globals.css`, and the Bifrost images in `public/` are copied from [Maxim AI Bifrost](https://github.com/maximhq/bifrost) commit `6493abd3d1422c9bfde95f242fd57b38e73ce881` (`ui/`). `globals.css` adapts Tailwind source scan paths; `textarea.tsx` drops the unused autosize variant and its dependency. `src/lib/constants/icons.tsx` keeps the upstream provider SVG definitions with a minimal theme-wrapper adaptation.
