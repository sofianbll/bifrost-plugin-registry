## Vérification

- `make check` : Go vet, tests avec détecteur de courses, tests UI, TypeScript, compilation React, conversion Python et syntaxe shell passent. L’installation verrouillée npm ne signale aucune vulnérabilité. Le build garde l’avertissement préexistant de taille du bundle ; aucune dépendance n’est ajoutée.
- Régressions backend : liste native sans secret, détail erroné/inactif/expiré/masqué, refus d’administration, absence d’inférence en cas de clé invalide ; Chat Completions et Responses restent couverts.
- Régressions éditeur : le changement de fournisseur construit l’identifiant exact sans changer l’identifiant natif, les corrections et les liens explicites.
- **18/18 parcours navigateur reproductibles** : [tests/ux_journeys.cjs](../../tests/ux_journeys.cjs) avec le serveur [tests/ui-fixture](../../tests/ui-fixture/README.md). La vraie interface compilée utilise le vrai serveur HTTP et la persistance Registry ; le transport Bifrost est synthétique. Les tests de grand catalogue et d’indisponibilité injectent uniquement des réponses de présentation. Sont inclus Retour/Suivant, brouillons, erreurs de publication, échec du presse-papiers, 65 modèles, mobile 390 × 844, clair/sombre et absence d’erreur JavaScript. Les captures et le rapport détaillé sont dans `dist/checks/ux-audit/`, ignoré par Git.
- Relecture indépendante : audit logique et audit de conformité aux spécifications par deux agents distincts, puis revue visuelle des captures desktop/mobile et clair/sombre. Cela ne remplace pas un essai par un utilisateur réel.
- Relecture des tests : cible navigateur fixée à la fixture locale avant toute requête ; mesure de position sans capture d’élément qui le ferait défiler artificiellement dans la zone visible.

Pour reproduire les parcours : compiler `ui/`, lancer `go run ./tests/ui-fixture` dans un terminal, puis `node tests/ux_journeys.cjs` dans un second avec Playwright disponible. `PLAYWRIGHT_MODULE` et `CHROMIUM_PATH` permettent d’utiliser les outils déjà installés ; voir `tests/ui-fixture/README.md`. Utiliser un serveur de fixture neuf par passage ; le test refuse une connexion dont la version n’est pas `2.2.3-fixture`.

## Limites

Ces corrections conservent le domaine, les droits natifs, la distinction référence/accès, les corrections manuelles et le protocole de publication. Aucun fournisseur réel, donnée personnelle ou déploiement de production n’est nécessaire aux tests. La release publiée et les instances existantes ne sont pas modifiées par la qualification de ce candidat.

Les audits heuristiques ne certifient pas l’accessibilité complète et n’établissent pas une note de satisfaction utilisateur. Le laboratoire reste différé. Une qualification native n’est valable que pour la paire gateway/plugin et l’architecture effectivement testées ; les résultats de compilation source et navigateur ne la remplacent pas.
